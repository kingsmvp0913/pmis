# 自動修正流程(2026-11-11)

取代「下載辨識問題 ZIP → 搬到開發機 → 說『修改』→ 重開」的人工轉手。使用者定的條件:
全自動(不要人工核准)、直接防提示注入、可改範圍 = 讀取器 + 驗證規則、承辦人可附說明、
原始檔處理完就清掉、右上角標籤提醒重啟。

## 一、整體流程

```
承辦人在 PMIS 按「送出辨識問題」(可附 500 字內說明)
   │ (1) 伺服器重新解析驗證,只把真的驗得出來的問題連同原始檔、系統資料推進私人佇列 repo
   │     的 待修正/<批號>/,並寫 狀態/<批號>.json = 排隊中
   ▼
私人佇列 repo ── on: push paths 待修正/** ──▶ GitHub Actions(Windows 主機)
   │ (2) 寫 狀態 = 處理中;用 check-batch.js 記下修改前的硬錯數
   │ (3) Claude 依 .claude/skills/fix-queue 處理(白名單工具,拿不到 push 權杖),只在本機 commit
   │ (4) workflow 自己把關:範圍與危險寫法 → 全套測試 → 那批硬錯變少;全過才推上程式 repo
   │ (5) 寫 狀態 = 已修好 / 需要決定 / 沒修成;刪掉問題包並壓掉佇列 repo 歷史
   ▼
PMIS 伺服器每 5 分鐘讀 狀態/ → 右上角標籤;承辦人用「啟動.bat」重開後,
本機已含該 commit 的批次標籤自動消失
```

GitHub 端只在收到問題包時才跑,平常不耗用。

## 二、各部分

### A. 佇列 repo(私人)
範本與設定步驟在 `deploy/pmis-queue/`(README + workflow)。
- `待修正/<批號>/`:`辨識問題列表.csv`、`原始檔案/`、`系統資料/`(期初、已寫入日誌、契約、`工程.json`)、`承辦人說明.txt`(有填才有)。
- `狀態/<批號>.json`:`{ 批號, 指紋, 工程, 狀態, 更新時間, 摘要[], 需要決定[], 放寬規則[], 原因, commit }`。只有文字,結案 30 天後清掉。
- 批號 = 本機流水號 + 內容指紋前 6 碼(兩台電腦同一天都會有 -0001)。同內容重送不重建,除非上次沒修成。

### B. PMIS 伺服器
- `data/config.json`:`GITHUB_TOKEN`、`QUEUE_REPO`。沒設定就只有原本的下載 ZIP。
- `POST /api/projects/:id/daily-logs/recognition-issues/submit`(`daily-log-routes.js`):與廠商問題標註共用 `revalidate`,
  **前端送來的問題文字不收**,只收伺服器驗得出來的;說明限 500 字。佇列操作在 `fix-queue.js`(Git Data API 一次 commit,ref 被拒重試)。
- `GET /api/auto-fix/status`:快取 5 分鐘;`git merge-base --is-ancestor` 判斷本機是否已含修正;處理中超過 1 小時 → 處理逾時。
- `scripts/git-auth.js`:start.js 每次啟動把權杖寫進本機 `.git/config` 的 extraheader,`啟動.bat` 的 git pull 才拉得到私人 repo。

### C. 前端
- 施工日誌問題清單:「送出辨識問題」+ 說明欄(設定了佇列才出現),沿用「問題歸屬」只送辨識問題。
- 右上角標籤 `auto-fix-tag.js`:請重新啟動 > 需要決定 > 沒修成 > 處理逾時 > 處理中 > 排隊中;點開逐批列出摘要、需要決定、**放寬規則**。

### D. 防提示注入(施工日誌與承辦人說明都會被 Claude 讀)
1. **伺服器**:問題清單不收前端文字(`revalidate` + `verifiedProblems`)。
2. **Claude 的權限**:`--allowedTools` 白名單(讀寫檔、node、jest、git add/commit/看),禁 WebFetch/WebSearch/git push/remote/config/curl;
   兩個 checkout 都 `persist-credentials: false`,push 權杖只在最後推送那一步。
3. **workflow 固定把關**(不靠 Claude 自述,全過才推):
   - `fix-queue-gate.js`(用修改前那一版):只准改讀取器、`daily-log-validate.js`、測試與 fixture、缺陷登記、讀取器 SKILL;
     讀取器與驗證規則新增的程式不准有 require/import/process/全域物件/網路/動態執行/外部程式/檔案系統/網址;測試不准連網、跑外部程式、動態執行。
     拿過去 19 個佇列修正驗過:14 個通過,5 個改到範圍外(上傳流程、報表保護、前端、來源定位)→ 這類會變「需要決定」。
   - 全套測試(`SP0_SKIP_EXCEL=1`,這一步沒有權杖)。
   - `check-batch.js`:用系統資料重跑那批,修改前後比硬錯數,沒有一批變少或任何一批變多 → 不推。
   - 推送時與最新版本衝突 → 不推。
4. **剩下的風險**:Claude 能跑自己寫的 node 腳本(查 PDF 一定要),理論上可連網把 `CLAUDE_CODE_OAUTH_TOKEN` 送出去。
   最壞是被盜用 Claude 額度;程式推不上去。發現就撤銷重發。

### E. 處理步驟
`.claude/skills/fix-queue/SKILL.md`:安全規則、步驟、結果檔格式、歷次踩過的坑(雲端讀不到本機記憶)。

## 三、要使用者做的設定(一次性)
見 `deploy/pmis-queue/README.md`。**順序**:先 push 本流程 → 使用者重開一次(拿到 git-auth)→ 填權杖並確認拉得到 →
最後才把程式 repo 改成私人,否則使用者的自動更新會斷掉。
