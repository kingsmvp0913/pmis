# 自動修正流程(2026-11-11)

取代「下載辨識問題 ZIP → 搬到開發機 → 說『修改』→ 重開」的人工轉手。使用者定的條件:
全自動(不要人工核准)、直接防提示注入、可改範圍 = 讀取器 + 驗證規則、承辦人可附說明、
原始檔處理完就清掉、右上角標籤提醒重啟。

## 一、整體流程

```
承辦人在 PMIS 按「送出辨識問題」(可附 500 字內說明)
   │ (1) 伺服器重新解析驗證,只把真的驗得出來的問題連同原始檔、系統資料推進本 repo 的
   │     fix-queue 分支 待修正/<批號>/,寫 狀態/<批號>.json = 排隊中,再發 repository_dispatch
   ▼
main 上的 .github/workflows/fix-queue.yml(只用內建 GITHUB_TOKEN + CLAUDE_CODE_OAUTH_TOKEN)
   │ (2) 標處理中 → Claude 修(白名單工具、無寫入權限)→ 匯出 patch
   │ (3) 全新主機把關:範圍與寫法 → 全套測試 → 那批硬錯變少;全過才推上 main
   │ (4) 寫 狀態 = 已修好 / 需要決定 / 沒修成;刪掉問題包並壓掉 fix-queue 分支歷史
   ▼
PMIS 伺服器每 5 分鐘讀 狀態/ → 右上角標籤;承辦人用「啟動.bat」重開後,
本機已含該 commit 的批次標籤自動消失
```

佇列放在程式 repo 的分支而不另開 repo:workflow 才能用內建權杖讀寫程式,使用者那邊只要**一組**權杖(啟用碼)。
推到 fix-queue 分支不會觸發 main 上的 workflow(GitHub 去那個分支找 workflow),所以送完另發 repository_dispatch。
GitHub 端只在收到問題包時才跑,平常不耗用。

## 二、各部分

### A. 佇列(fix-queue 分支)
- `待修正/<批號>/`:`辨識問題列表.csv`、`原始檔案/`、`系統資料/`(期初、已寫入日誌、契約、`工程.json`)、`承辦人說明.txt`(有填才有)。
- `狀態/<批號>.json`:`{ 批號, 指紋, 工程, 狀態, 更新時間, 摘要[], 需要決定[], 放寬規則[], 原因, commit }`。只有文字,結案 30 天後清掉。
- 批號 = 本機流水號 + 內容指紋前 6 碼(兩台電腦同一天都會有 -0001)。同內容重送不重建,除非上次沒修成。
- **repo 還公開時伺服器拒絕送出**(施工日誌會外流);已貼啟用碼也只拿來拉更新。

### B. PMIS 伺服器
- `data/config.json` 的 `GITHUB_TOKEN`:承辦人重開後**自動跳出的啟用視窗**貼一次(`PUT /api/auto-fix/activate`,
  先驗證能寫這個 repo 才存,並立即同步 git pull 憑證)。repo 取本機 git origin。沒啟用就只有原本的下載 ZIP。
- `POST /api/projects/:id/daily-logs/recognition-issues/submit`(`daily-log-routes.js`):與廠商問題標註共用 `revalidate`,
  **前端送來的問題文字不收**,只收伺服器驗得出來的;說明限 500 字。佇列操作在 `fix-queue.js`(Git Data API 一次 commit,ref 被拒重試)。
- `GET /api/auto-fix/status`:快取 5 分鐘;`git merge-base --is-ancestor` 判斷本機是否已含修正;處理中超過 1 小時 → 處理逾時。
- `scripts/git-auth.js`:start.js 每次啟動把權杖寫進本機 `.git/config` 的 extraheader,`啟動.bat` 的 git pull 才拉得到私人 repo。

### C. 前端
- 施工日誌問題清單:「送出辨識問題」+ 說明欄(設定了佇列才出現),沿用「問題歸屬」只送辨識問題。
- 右上角標籤 `auto-fix-tag.js`:請重新啟動 > 需要決定 > 沒修成 > 處理逾時 > 處理中 > 排隊中;點開逐批列出摘要、需要決定、**放寬規則**。

### C2. 沒有讀取器 / 整份讀不動(2026-11-11 加)
- parse 回 `可送出讀取器`(找不到這家讀取器,或讀取器整份讀不動;只少選一聯不算)→ 畫面出現「送出,自動產生或修正讀取器」+ 說明欄。
- `POST /api/projects/:id/daily-logs/parser/submit`:伺服器自己重判條件(讀得動的擋回去走送出辨識問題);
  `工程.json` 帶 `類型`(新讀取器/讀不動)與 `讀取器`(廠商主檔名,新讀取器的 `meta.vendorKey` 要一字不差)。
- Claude 照 `gen-vendor-parser` 產生或修正;判定改善 = 從讀取失敗變讀得動。重開時 onboarding 自動安裝新讀取器。
- 來源定位(`daily-log-source-locator.js` 的 PROFILES,畫紅框用)不在自動範圍 → 結果裡列為「需要決定」,由開發者補。

### D. 防提示注入(施工日誌與承辦人說明都會被 Claude 讀)
1. **伺服器**:問題清單不收前端文字(`revalidate` + `verifiedProblems`);說明限 500 字;Claude 寫的結果文字只收字串、限筆數與長度,畫面以純文字顯示。
2. **五個互不相通的 job**(`.github/workflows/fix-queue.yml`):同一個 job 裡 Claude 能改 git hook、`$GITHUB_ENV`、
   後面步驟要跑的腳本,所以權杖絕不和它同 job。
   - `prepare`:標處理中、記下程式 repo 基準版本。
   - `fix`:只有 Claude 金鑰、唯讀;`--allowedTools` 白名單(讀寫檔、node、jest、git add/commit/看),禁 WebFetch/WebSearch/git push/remote/config/curl;
     改完匯出成 patch。
   - `gate`:**全新主機**從基準版本 `npm ci`、套 patch;範圍與寫法檢查 → 全套測試;沒有任何權杖;通過與否看步驟成敗(runner 判定,測試碼改不了)。
   - `verify`:**再一台全新主機**,修改前後各跑一次那批比硬錯數;不跑測試(測試碼碰得到檔案,不能和修改前的數字放同一台)。
   - `publish`:**全新主機**用 main 上的程式、停用 git hook,套 patch 後再檢查一次範圍才推;不執行 patch 裡的程式。
3. **gate / verify 的三道檢查**(全過才推):
   - `fix-queue-gate.js`(用基準版本那份):只准改讀取器、`daily-log-validate.js`、測試與 fixture、缺陷登記、讀取器 SKILL;
     改到的程式檔**整份解析成語法樹**(`@babel/parser`),與修改前**逐項**比(問題種類 + 出現在哪段程式,
     刪一個合理的 `require` 換成危險的照樣擋),不得新增 require/process/全域物件/網路/動態執行/計時器、
     `.constructor`/`__proto__`/`prototype`、拼湊字串當屬性名、`fromCharCode`、`module`(只准 `module.exports`);
     測試另不准轉存 `require`、用 `module`、`process.mainModule`、寫出系統模組名字串;解析不了直接拒絕。
     拿過去 19 個佇列修正驗過:14 個通過,5 個改到範圍外 → 這類會變「需要決定」。
   - 全套測試(`SP0_SKIP_EXCEL=1`)。
   - `check-batch.js`:用系統資料重跑那批,修改前後比硬錯數,沒有一批變少或任何一批變多 → 不推。
4. **剩下的風險**(使用者已知悉,選擇全自動):
   - 靜態檢查原理上擋不完刻意混淆的程式,例如用廠商檔案裡的文字當屬性名一路拼出危險呼叫;讀取器在伺服器裡**沒有執行隔離**。
     真正的解法是讓讀取器在隔離環境執行(另一個工程)。
   - Claude 能跑自己寫的 node 腳本(查 PDF 一定要),可連網把 `CLAUDE_CODE_OAUTH_TOKEN` 送出去。最壞是被盜用 Claude 額度;程式推不上去。

### E. 處理步驟
`.claude/skills/fix-queue/SKILL.md`:安全規則、步驟、結果檔格式、歷次踩過的坑(雲端讀不到本機記憶)。

## 三、要使用者做的設定(一次性)
1. 建一組 fine-grained 權杖(只選 `pmis`,Contents **Read and write**,1 年)當「啟用碼」,傳給承辦人。
2. `claude setup-token` → `gh secret set CLAUDE_CODE_OAUTH_TOKEN -R <帳號>/pmis`。
3. **順序**:承辦人重開(拿到啟用視窗)→ 貼啟用碼 → 確認拉得到更新 → **才把 repo 改成私人**;改私人之前送出按鈕不會出現。
