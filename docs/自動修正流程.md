# 自動修正流程(規格草案,2026-11-11)

取代現行「下載辨識問題 ZIP → 搬到 D 槽 → 說『修改』→ 重開」的人工轉手。

## 一、整體流程

```
承辦人在 PMIS 按「送出辨識問題」
   │ (1) 伺服器把問題包推進私人佇列 repo 的 待修正/<批號>/,並寫 狀態/<批號>.json = 排隊中
   ▼
私人佇列 repo ── on: push paths 待修正/** ──▶ GitHub Actions(Windows 主機)
   │ (2) 第一步寫 狀態 = 處理中
   │ (3) Claude 依 .claude/skills/fix-queue 處理:查根因 → 修 → 全套測試 → 原始檔重跑
   │ (4) 通過把關才 push 到程式 repo;寫 狀態 = 已修好 / 需要決定 / 沒修成(附摘要與 commit)
   │ (5) 刪掉問題包並壓掉佇列 repo 歷史(原始檔不留在 git 歷史裡)
   ▼
PMIS 伺服器每 5 分鐘讀 狀態/ → 右上角標籤;承辦人用「啟動.bat」重開後,
本機已含該 commit 的批次標籤自動消失
```

GitHub 端只在收到問題包時才跑,平常不耗用。

## 二、各部分

### A. 佇列 repo(私人,使用者建立)
- `待修正/<批號>/`:與現行 ZIP 內容相同(`辨識問題列表.csv`、`原始檔案/`、`系統資料/`)。
- `狀態/<批號>.json`:`{ 批號, 工程, 狀態, 更新時間, 摘要[], 需要決定[], commit }`,只有文字摘要,不含原始檔。
- `.github/workflows/fix-queue.yml`:見 D。

### B. PMIS 伺服器
- `data/config.json` 新增 `QUEUE_REPO`(如 `帳號/pmis-queue`)與 `QUEUE_TOKEN`(fine-grained 權杖,**只給佇列 repo 的 Contents 讀寫**)。沒設定就維持現行下載 ZIP,不報錯。
- 新路由 `POST /api/projects/:id/daily-logs/recognition-issues/submit`:沿用現行 ZIP 的組法,改用 GitHub Git Data API **一次 commit** 推進佇列;同一批(原始檔雜湊+問題清單相同)重送時不重複建立。
- 狀態輪詢:每 5 分鐘讀 `狀態/`,並以 `git merge-base --is-ancestor <commit> HEAD` 判斷本機是否已更新到含修正的版本;快取給前端 `GET /api/auto-fix/status`。
- 「處理中」超過 1 小時沒變 → 顯示「處理逾時」。

### C. 前端
- 施工日誌問題彈窗:「下載辨識問題」旁加「送出辨識問題」(設定了佇列才出現);沿用承辦人勾的「問題歸屬」,**只送辨識問題**。
- 右上角標籤(平常不顯示):排隊中 ⏳/處理中 🔧/有更新請重新啟動 🔄/需要決定 ⚠️/沒修成 ❌,同時多批時顯示最需要處理的那個,點開逐批列出。配色走 `app.css` 變數。

### D. GitHub Actions(佇列 repo)
- `on: push: paths: ['待修正/**']` + `workflow_dispatch`;`concurrency: fix-queue`(一次一批,其餘排隊)。
- `runs-on: windows-latest`;checkout 佇列 repo 與程式 repo(後者用 `PMIS_PUSH_TOKEN`);安裝 Noto Sans TC(主機沒有繁中字型)。
- 叫 Claude:`anthropics/claude-code-action`,憑證用 `CLAUDE_CODE_OAUTH_TOKEN`(綁 Claude 訂閱)或 `ANTHROPIC_API_KEY`(依用量計費)。
- **把關**:`SP0_SKIP_EXCEL=1` 全套測試綠 + 原始檔以系統資料重跑、那批硬錯消失,才 push;否則不 push,狀態寫「沒修成」並附原因。
- 狀態檔用 Actions 自己的 `GITHUB_TOKEN` 寫,不會再觸發 workflow。

### E. 處理步驟要進 repo
雲端的 Claude 讀不到本機記憶。現行 `d-drive-fix-queue` 記憶的步驟與踩過的坑,整理成
程式 repo 的 `.claude/skills/fix-queue/SKILL.md`(不含任何原始檔內容)。

## 三、要使用者做的設定(一次性)
1. 建私人 repo(建議名 `pmis-queue`)。
2. 建兩組 fine-grained 權杖:佇列 repo Contents 讀寫(填進 PMIS 的 `config.json`)、程式 repo Contents 讀寫(存成佇列 repo 的 secret `PMIS_PUSH_TOKEN`)。
3. 佇列 repo secret 放 Claude 憑證(`claude setup-token` 產生的 `CLAUDE_CODE_OAUTH_TOKEN`)。
