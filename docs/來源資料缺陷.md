# 來源資料缺陷登記簿

系統報出來的硬錯，有一部分**不是系統讀錯，是來源文件本身就不一致**。
那類問題查證一次要花掉半小時到一輪，而且**每個新 session 都會重新查一次**，
所以查過就登記在這裡。

## 什麼該記進來

只記**已經逐格查證過、確定不是讀取器讀錯**的那種。判準：

- 拿原始儲存格／PDF item 對過，讀取器讀到的值與文件上印的值一致；
- 而該值與另一份文件（發包後經費總表、決標公告、專案主檔）對不起來。

**不記**「還沒查清楚」的異常——那會讓下一個人以為查證過了，比不記更貴。
也不記讀取器的坑（那寫在各讀取器的檔頭）。

## 格式

每筆一節，標題是「案名 — 一句話講清楚哪兩份文件對不起來」，內文四段：

1. **證據**：兩邊的實際值、在哪個儲存格／哪一頁。
2. **影響**：系統會報出哪個規則碼、幾筆。
3. **判定**：為什麼確定是來源不一致，不是讀錯。
4. **處置**：系統照讀不抹平；要不要改由承辦人決定。

## 待問清單（承辦人 2026-08-13 要求彙整，之後一次問）

系統判斷不了「該改哪一份」，只有承辦人問得到。逐筆的證據看下面各節。

| # | 要問誰 | 問什麼 |
|---|---|---|
| 1 | 坤曜 或 台西國中 | 「砌1/2B磚牆」的契約數量是 **11.55 M2**（施工日誌）還是 **12**（發包後經費總表）？單價兩邊都是 1188，其餘 33 項一致。是日誌打錯，還是經費總表有變更設計沒反映到日誌？ |
| 2 | 寶嶸 或 橋頭國小 | 施工日誌的逐項單價（項1 = 16,250）與兩份發包後經費總表（橋頭 9,750／許厝 10,250）都不同，**但總額都等於決標金額 4,349,520**。是廠商自行把兩個標的的金額重新分配了嗎？另外橋頭與許厝兩份日誌用的是**同一套單價**，這樣對嗎？ |
| 3 | 承辦人自己 | `義賢國小廁所_開工報告表(日期有誤).pdf` 檔名寫「日期有誤」——是哪一個日期有誤？（決標日 2026-07-24／開工 2026-07-31／竣工 2026-11-13） |

⚠️ 第 3 題不是來源不一致，是**還沒查證**的項目，答案回來之前不要引用它下結論。

## 台西國中西側廁所（坤曜）— 日誌的契約數量比經費總表少 0.45 M2

1. **證據**：項次 6「砌1/2B磚牆」，施工日誌寫 **11.55 M2**
   （`台西廁所施工日誌(1).XLSX` → `日報表(7)` 明細列的契約數量欄），
   發包後經費總表寫 **12**（`台西國中教學大樓西側廁所整修工程_發包後經費總表（工管費分開)-3.xls`
   → `詳細價目表`）。單價兩邊都是 1188。其餘 33 項全部一致。
2. **影響**：SP3 的 **E5 × 31**（每天一筆，31 天）。硬錯，會擋住整份歸檔。
3. **判定**：讀取器讀的是儲存格原值，逐格核對過；34 項裡只有這一項不同，
   若是欄位錯位會整排錯。
4. **處置**：照讀不抹平。要嘛廠商改日誌、要嘛經費總表有變更設計沒反映到日誌。

## 橋頭國小暨許厝分校（寶嶸）— 兩個標的的金額被重新分配過，兩份日誌還共用同一套單價

1. **證據**：決標金額 4,349,520，拆成兩份發包後經費總表：
   橋頭國小 1,670,374 + 許厝分校 2,679,146 = 4,349,520 ✅。
   但施工日誌的單價與**兩份都不同**，而且橋頭與許厝兩份日誌用的是**同一套單價**：

   | 項次 | 橋頭經費總表 | 許厝經費總表 | 兩份日誌 |
   |---|---|---|---|
   | 1 工程告示牌 | 9,750 | 10,250 | 16,250 |
   | 2 施工動線開闢 | 9,000 | 21,000 | 50,000 |

   日誌自身是自洽的（數量 × 單價 = 合計，33 項加總 = 該檔總計列：
   橋頭 1,993,432、許厝 2,356,088，兩者相加也等於 4,349,520）。
2. **影響**：SP3 的 **E6 × 1860**（33 項 × 60 天，扣掉對得上的）。硬錯。
3. **判定**：讀取器讀的是 `工程進度表` 的單價欄（欄 6），與合計欄（欄 7）自洽，
   33 項加總等於總計列。欄位讀錯不可能還維持這三重自洽。
4. **處置**：照讀不抹平。抹平會讓「兩個標的的金額分法不同」這件事永遠看不到，
   而那正是[一單多標的]那條線要面對的核心問題。

## 元長國小校園鋪面（有謙）— 工程名稱那格從第 3 天起是數值 0

1. **證據**：`施工日誌-雲林縣元長國小舖面.xlsx`，30 天裡只有前 2 天的
   「工程名稱」欄有字，第 3 天起 28 天都是數值 `0`（列 133、194、255…）。
2. **影響**：讀成字串 "0" 的話 SP3 每天噴一個 G1（工程名稱與主檔不一致），
   而且畫面上工程名稱顯示「0」。
3. **判定**：儲存格型別是 number、值是 0，不是字串也不是空白。
   那是 Excel 對空公式的顯示值。
4. **處置**：讀取器把文字欄的 `0` 視為無資料標記回 null（寫在 `youqian.pmisparser.js`
   的 `text()`）。**這是辨識無資料標記，不是改寫來源值。**

## 元長國小廁所（賜利發）— 本日金額欄與累計金額欄各自四捨五入，合計差幾元

1. **證據**：`7月公共工程施工日誌-元長國小廁所(修.xls` 第二聯，
   7/12 那天各項「累計金額欄」加總 = **16,910**（也就是合計列印的值），
   而逐日累加「本日完成金額欄」得到 **16,912**。差 2 元。
2. **影響**：SP3 的 **B4 × 19**。硬錯。
3. **判定**：兩欄都是廠商自己算的，各自四捨五入成整數
   （例：職安衛單價 9,406 × 0.008 = 75.248 → 印 75）。累到 33 項必然差幾元。
4. **處置**：**這一筆的責任在系統不在來源**——B3 的容差會隨累加筆數放寬
   （`0.5 × 筆數`），B4 卻固定 0.5 元。修法比照 B3。
   ⚠️ 列在這裡是因為查證路徑相同，但它是**待修的系統缺陷**，不是來源缺陷。

## 公誠國小 7 月日誌（富森）— 一份檔混了兩個標案的資料

1. **證據**：`公誠國小-7月施工日誌 2.pdf` 共 119 天，前段是 2026-07-16~09-22
   （實際進度 1.22% → 9.78%，其後整段空白），後段跳回 2025-08-12~09-30
   （實際進度 59.44% → 115.74%）。兩段的明細列數也不同（38 vs 36）。
2. **影響**：不分日期一起算會導向完全錯誤的結論（累計、進度、金額全部混算）。
3. **判定**：日期序列不連續且回跳一年，明細結構也不同。
4. **處置**：**分析這份檔時一定要先分段**。四湖那案的日誌樣本也有同樣情形。
