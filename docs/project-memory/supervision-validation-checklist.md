使用者提供 `OneDrive\Desktop\監造報表_施工日誌驗證檢查清單_v1.xlsx`(分頁「說明」+「檢查清單」),列出「由施工日誌自動產出監造報表前」要跑的 48 條驗證,分 10 大類 A–J。屬 [[supervision-report-pipeline]] 的 SP3。

- 嚴重度:**硬錯誤=阻擋產出**(未修正不產表,列出所有錯誤位置:哪天/哪項次/哪欄);**軟警告=標示但可產**。使用者已確認採「硬錯阻擋+列全部錯誤,不給強制產出」。
- 客戶已在「客戶決定(納入?)」欄逐條勾 是/否:多數是,少數否(B1 本日金額=單價×數量、D2 編號日期段、G5 工程編號、H2 進度與金額、I1/I2/I3 出工人力)。實作時照此欄納入/略過。
- 資料來源:施工日誌 header、施工日誌 dailyRows、契約詳細價目表(=監造報表活頁簿內建,SP2 由發包經費總表建)、專案主檔、parseAll 跨天。
- E 類(契約表核對 7 條)+ C2 需契約詳細價目表當權威基準→到 SP3 時 SP2 已建好,故此時可跑。
- 一律台灣四捨五入 ROUND_HALF_UP,非 Excel 銀行家捨入。
- 備註欄客戶留的待釐清:E3 項目名稱一致「應改硬錯誤?」、C1「標示從哪天開始錯」、F4「期末指當期還竣工」、J2/J3「是否與單位一致重複」——寫 SP3 spec 時要逐一定案。

寫 SP3 spec 時把此 xlsx 原樣附為附錄依據。
