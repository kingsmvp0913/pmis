# gen-vendor-parser skill 改進筆記（累積中，最後一併改 SKILL.md）

## N1. 沒教「樣本檔找不到廠商名時去哪找」

`yusen.pmisparser.js` 檔頭自己寫著 `⚠️ vendorKey 待確認`——樣本檔的簽名欄空白，
當初**依命名慣例推定**成「玉森營造有限公司」。實際 5 案的決標公告一致寫「玉森土木包工業」。

後果：`org-match.findByName` 逐字相等 → 讀取器完全讀得動卻**永遠叫不出來**，
5 案 71 份日誌閒置，而且**沒有任何錯誤訊息**，看起來就像「這家還沒有讀取器」。

**該補**：vendorKey 的權威來源是**決標公告的得標廠商**（`winningVendor`）。
樣本檔查不到就去查該工程的決標公告。**禁止推定**。
並且**測試要斷言 `meta.vendorKey`**——原本沒有任何測試驗它，所以錯名字能一直躺著。

## N2. 沒有「產新讀取器前先確認現有的能不能用」這一步

該補成產線第 0 步：拿現有每一支對新樣本跑一遍。
判斷是否命中要看「天數/列數/**有名稱列數**」——只讀到 1–25 列、有名稱 1–2 是**假陽性**
（和穩/義鼎/嘉原對 jinda 就是這樣）。

## N3. 第 0 步的取樣會漏：一家多案多格式時只測一份樣本不夠

長澤營造有 2 案，兩案**版面完全不同**（中和＝`基本|封面|施工|監造|工作表1`、
三崙＝`封面|日報|施工項目`）。第 0 步只挑「最大的一份」＝中和，結果沒測到三崙——
而三崙其實**現有的承昇讀取器就讀得動**（51 天 / 1530 列 / 全部有名稱）。

**該補**：第 0 步要**每案至少各測一份**，不是每家一份。

## N4. 沒教「範本殘留的廠商名不可信」

三崙案的「施工項目」分頁第 0 列寫著「承昇營造有限公司」，但決標公告的得標廠商是
長澤營造。那是拿承昇的檔改的殘留。**日誌內的廠商名只能當佐證，不能當權威**——
與 `sp2-budget-sheet-findings` 的「第一張分頁是南陽殘留」是同一類陷阱。

## N5. 架構限制：共用版面無法共用程式碼

三崙（長澤）與明倫（承昇）是同一套版面。但 registry 是「一 vendorKey 一支讀取器」，
且讀取器裝到 `data/vendor-parsers/`（無 node_modules、無相對路徑），
**除了注入的 `ctx.filetypes` 之外不能 require 任何東西**。
所以同版面只能整份複製 200+ 行。

**該補**：要嘛在 skill 明講「同版面就是複製，這是刻意的取捨」，
要嘛把常見版面（工程會標準表單的幾個變體）做進 `filetypes/` 當共用解析器。
後者才是根治——目前 25 家裡至少已看到 2 組共用版面。

## N6. 沒教「標籤寫的和值的語意可能不同」

祥賀 r0+60 欄 24 的標籤是「每日施工金額**累計**」，但值是**當日**金額
（01-06=52677、01-07=15107 遞減，兩者相加正好等於第 2 天的累計總和）。
照標籤收下來的話 SP3 的 B4 每天硬錯，實測 239 項。

**該補**：金額/累計類欄位取值後要**用另一種算法交叉核對**再收下
（單價×數量=複價、逐日累加=累計）。標籤不是證據。

## N9. 第 0 步之前還缺一步：確認「這家到底有幾份日誌」（2026-08-08 宜謙）

盤點靠檔名關鍵字（日誌/日報/施工紀錄）抓日誌，但**有一整類日誌是用日期區間命名的**
（`0601A-0630A.pdf`、`8.27-8.31.pdf`、`鎮西0701A-0731A.pdf`、`0923A-0930A.xlsx`）。
宜謙因此被記成「5 案只有 6 份 PDF、其中 3 案沒有日誌」，實際是 **5 案 25 份**，
而且漏掉的那幾份裡有**沒有掃描問題的 .xlsx 版**——等於用最難的來源做了半天。
禾結更誇張:被記成「沒有日誌」,實際有 3 份。

**該補**：產線第 0 步之前先確認來源清單，判定「是不是日誌」不要只看檔名關鍵字；
`data/parser-tools/relist-logs.js` 是修好的版本（關鍵字 OR 日期區間，再扣掉
監造報表/經費總表/決標公告/開工報告/試算表）。`batch-check.js` 內建的濾條也一樣要改。

## N8. Excel 篇沒教「合併填充會毀掉區塊的結束條件」（2026-08-08 久木）

skill 的 Excel 坑只講「合併區起點值會填滿整個合併區，用起點欄取值即可」，
沒講反面：**填滿之後，grid 上再也沒有「整列皆空」這回事**。拿它當一個區塊的
結束條件（`if (整列皆空) break`），迴圈會一路跑到分頁末端。久木的材料區因此
把整個第一聯的段落標題與安衛檢查事項都收成「主要材料」——而且 `extras` 沒有
任何完整性關卡在看，三關全過。

同一個成因的第二種症狀：**表頭上合併 6 欄的「材料名稱」會被當成 6 個獨立區塊**，
同一筆材料收 6 次，其中 5 筆的單位/數量還是 null。

**該補**：①區塊的界一律用「段落標題／下一個表頭／已知錨點」，不用空白列；
②要用表頭定位欄位時，先把表頭列壓成「連續同值只留最左欄」的分段。

## N7. filetypes 沒有 docx，但 skill 寫得像有

skill 的「分層架構」列了 `Word(docx.js):mammoth 或解 word/document.xml`，
但 `filetypes/index.js` 只 re-export `pdf.js` 與 `xlsx.js`。**`docx.js` 不存在**。
樣本裡有大量 .docx 日誌因此一律讀不了。

## N10. 沒教「項次要不要加前綴，答案在發包後經費總表裡」（2026-08-08 宜謙）

skill 完全沒提前綴這件事，記憶的招式 2 又只說「多張表各自從 1 編號時要前綴大類」，
照字面做會前綴成「壹.1」——而**經費總表的項次是 1..N**，於是每天每列一個 E1 硬錯。
宜謙同一家 4 案就分成兩種：2 案沒有中類（不可前綴）、2 案有中類（必須前綴）。

**該補**：判準寫成「拿該案的發包後經費總表（SP2 的 `parseItems`）看它怎麼編號，
與日誌對齊」，並講明副作用——`是費用項目 = !/^\d+$/.test(項次)`，前綴會讓
B2/F1/B3 從硬錯降成軟警告。

## N11. 沒教「同一家可能有兩種檔型、版面卻相同」（2026-08-08 宜謙）

skill 的分層架構是「一家一種檔型」的敘事，第 0 步也只挑一份樣本。宜謙同一套表單
有 PDF 與 xlsx 兩種產出，欄位完全一樣，但**進度欄的載體語意不同**（PDF「0.34 %」
是百分數、Excel 0.0034 是分數）。分開寫兩支或只寫一種都會出事。

**該補**：`parseAll` 依副檔名分流、欄位規則共用一份純函式、**selfTest 兩條路都要驗**。

## N12. 三關的「未通過」有一種是誤判：缺前期累計（2026-08-08 宜謙 / 久木）

`check-parser.js` 對單一檔跑 SP3，逐月檔的第一天帶著前面月份累積出來的累計數量，
F4 必然不符 → 印「未通過」。宜謙的石榴案更慘：開工那幾天的日誌是**無文字層掃描件**，
永遠補不回來，單檔與合併都會留下 F4。

**該補**：skill 要講「F4/B3 先用合併全案再驗一次」（記憶招式 13），並允許
「前期資料不可讀」當作已查明的結案理由——否則下一個人會一直改讀取器去追一個
資料面的缺口。

## N13. 名稱不一致（E3）不是讀取器的錯，但要當場說清楚（2026-08-08 宜謙）

宜謙的日誌把契約項目名寫成「產品,瀝青混凝土舖面,鋪設新品密級配AC(平均4cm)」，
經費總表寫「鋪設新品密級配AC(平均H4cm)」。E3 軟警告 1656 筆，看起來像讀取器
把名稱讀壞了，實際兩份文件本來就不同字。**不要為了讓 E3 歸零去截掉前綴**——
那是改寫來源值。

**該補**：交付報告要把「E3 軟警告數」與「名稱異常數（形狀健檢）」分開講，
前者是兩份文件的差異、後者才是讀取器的錯位。

## N14. 沒教「工程會標準表單是一個家族，錨點會假陽性」（2026-08-08 一次補 11 家）

24 家裡至少 8 家用同一份工程會標準表單（錨點都是「表報編號：」），版面只差
欄位落點與載體。skill 的「第 0 步：拿現有每支跑一遍」會因此**回報一堆假陽性**：
齊全的活頁簿被利成的錨點吃下去，回 94 個「有天數、每一天卻都是空的」結果。

**該補**：①第 0 步的判準要加「日期讀不讀得到」（現行只看天數/列數/有名稱數）；
②每一支用共通錨點的讀取器都要有一道「全部讀不到日期就 throw」的防線，
並寫成測試（拿別家的 fixture 餵進去，斷言它 throw）。

## N15. 沒教「項次要用出現序還是名稱，有客觀判準」（2026-08-08）

判準是「總明細列數 ÷ 天數」：每天都印完整清單的用出現序（與經費總表逐項同序）；
逐日只列當天施作的**一定要用名稱**——出現序跨天會指到不同項目，而 SP3 的
prevCum/dailySum 以項次為鍵，會把兩個項目的累計混在一起（沅隆實測 B2:45 → 0）。
代價要一併寫明：名稱當項次會讓 `是費用項目` 判成 true，B2/F1/B3 一起降成軟警告。

## N16. 沒教「PDF 跨行名稱的數值印在整塊的垂直中央」（2026-08-08 沅隆）

長名稱拆成 2~4 行時，數值那一行在整塊名稱的**中點**（實測四行 593.5/580.4/567.3/554.2、
數值 573.9 = 頭尾中點）。所以「離最近的數值列」是錯的判準（593.5 離上一列 8.6、
離自己 19.6）。做法：數值列自己那行沒有名稱時，一次收一上一下對稱擴張。
skill 目前只講「續行併入當前列」，那是單向的、會把別人的名稱接過來。

## N17. 沒教「出工/機具的欄界要包含累計欄」（2026-08-08 東震）

只給到「本日使用數量」的話，最後一格會從那裡吃到列尾：本日 1 與累計 1 併成 11。
一天內看起來只是數字大了一點，但同一案的 xls 與 PDF 兩條路會對不起來才被發現。
**凡是用「表頭起點 x 當欄界」的區塊，最後一欄的右界都要明確給**。

## N18. 沒教「.doc 完全做不了」（2026-08-08 宏恩）

N7 說 `docx.js` 不存在；更下面一層的問題是 **.doc（Word 97-2003 二進位）連讀都讀不了**：
它是 OLE2 檔（magic D0CF11E0），SheetJS 開不了（Cannot find Workbook stream），
而文字流雖然掃得到中文，**表格欄界在格式串流裡**，從文字流猜欄位就是編造。
**該補**：skill 要明講「.doc 請廠商另存 .docx/.xlsx，或先用 Word COM 轉檔」，
不要讓下一個人花時間試。
