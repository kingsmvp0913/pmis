2026-08-12 使用者的指示:**「commit 完先記憶」**。

每 commit 一筆,**下一個動作就是更新記憶**——不是做完一整輪才寫、更不是接著開始
下一項工作。

**Why:** commit message 記的是「這段程式為什麼這樣改」,但一輪工作真正值錢的東西
多半不在 diff 裡:量過但沒採用的做法、走過的死路、「以為是 A 其實是 B」的更正、
會賠掉下一輪的操作陷阱、還有規格問題的答案來自哪份證據。這些只要沒在當下寫進記憶,
context 一被壓縮或 session 一結束就沒了,**而下一個 session 會從零重做一次**。
commit 是天然的檢查點:那一刻剛好知道「這件事完成了、學到什麼」。

**How to apply:**
1. `git commit` 之後不要繼續寫程式,先更新記憶。
2. 更新的通常是三個地方,缺一不可:
   - **主題檔**——這一筆學到的東西(新建或改既有的那則)。
   - **狀態類的那則**(如 [[user-feedback-26-items]])——把該項從「未修」改成 commit hash。
   - **`MEMORY.md` 的接手點**——測試數字、commit 有沒有 push、下一輪從哪開始。
3. 接手點**只留一處**。踩過:索引開頭與清單那則各寫了一個不同的「下一輪先做這個」,
   開工先花一輪判斷該信哪個。
4. 過期的紀錄要**當場改掉或刪掉**,不是疊一則新的上去——舊的那則會被下一個 session
   照著追。
