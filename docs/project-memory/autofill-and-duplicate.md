## ① 契約工期沒有自動帶入 → `72f6475`

**根因不是忘了帶,是根本沒地方存**:`projects` 表只有 `duration_basis`(基準),
**沒有天數欄位**。開工報告表歸檔時只回寫四欄(編號/金額/開工日/竣工日),
工期整個沒進主檔,而畫面上還寫著「契約工期須對照開工報告表填寫,系統不會自動帶入」。

- 新增 `projects.duration_days`,歸檔時與基準一起回寫(只補空缺)。
- **天數與基準拆兩欄**:OCR 判不出基準時(24 份有 17 份兩個詞同時出現)天數仍要存得住。
- ⚠️ **`POST /basics` 原本存了 `duration_basis` 卻漏了天數**——承辦人在那張表單改的
  工期只進報表 B7,下次進畫面又被主檔的舊值蓋回去。基準當初加欄位的理由
  (「選了不存,每次進畫面又變回未知」)對天數一字不差地成立。

## ② 價目表寫入後要一併寫基本資料 → `92a056f`

**這就是 [[three-outputs-reconciliation]] 那三份產出「基本資料 9 欄全空」的成因。**
寫價目表與寫基本資料是兩顆獨立按鈕,做完前者不會帶到後者。

空白的後果不只那一頁,而且看起來像系統壞掉:封面整片印裸的 `0`(封面公式參照
基本資料)、完工期限 `=B8+B7-1` 算成 `-1`、每日施工紀錄的日期軸變成 `0,1,2…`。

值取自**主檔**不吃前端(沿用該路由「confirm 不吃前端送來的項目」的立場);
缺的欄位不產生指令,不會把已填的格清空;與價目表**併成同一批指令**送 Excel
——分開送要開兩次 COM,那是這條線上最慢也最容易失敗的一段。

## ③ 開工表彈窗沒用到全部範圍 → `5b72912`

**一個原因造成兩個症狀**,所以看起來像兩個 bug:
`.card` 在詳細頁限寬 720px(表單的合理閱讀寬度),而**彈窗裡的內容就是 `.card`**,
於是 958px 的可用空間只用 720px(右邊留白),表格要 754px 又被 `.table-wrap` 的
`overflow-x` 裁掉(「不符」標籤被切一半)。

既有 CSS 已經把彈窗裡 card 的背景/邊框/圓角/陰影都清掉了,**唯獨漏了 max-width**。
清掉後表格撐滿 895px,決標公告那串長工程名稱一行放得下(原本折行、連帶撐高整表)。

高度從寫死的 `max-height: 70vh` 改成 flex(`display:flex` + `min-height:0`):
70vh 是猜的,而標題列與(可能存在的)`.modal-actions` 各佔多少三個彈窗都不一樣
——**開工報告表的按鈕在 `.card` 內部,根本沒有 `.modal-actions`**。
695px 高的視窗實測:70vh 給 487px,flex 算出 607px。
⚠️ `min-height: 0` 不可省:flex 子項預設 `min-height:auto` 會拒絕縮到內容以下,
`overflow-y` 永遠不生效、modal 被內容整個撐出畫面外。

## ④ 一張決標拆兩個標的,要能複製工程 → `598b46c`

就是 [[user-feedback-26-items]] 第 24 項當初記著「沒做」的那半。
維持一標的一工程(既有裁決),補的是「第二個工程要把共同欄位重打一次」。

`POST /api/projects/:id/duplicate`,他選定的規格:
- **附件都複製過去**(決標公告 + 開工報告表)
- **決標金額照抄總額**,他自己拆(原話:「應該是我上傳附件後自己拆吧」)

⚠️ **複製範圍用排除清單不是列舉**:欄位會長(`duration_days` 就是同一天加的),
列舉法會讓新欄位默默不被複製,而那種漏最難發現——畫面上兩個工程長得一樣,
只有報表寫出來才看得到差別。排除 `name`/`actual_completion_date`/`firm_doc_no`。
契約項目與施工日誌**一律不複製**:那正是兩個標的不同的地方。

⚠️ 順手擋掉「照抄總額」的後遺症:忘了拆金額會撞到 SP2 的「合計與決標金額不符」,
而那句話會把他導去查價目表——**那份其實是對的**。現在同案號還有兄弟標的時,
訊息直接講「這張決標底下有 N 個標的,本工程的決標金額看起來還是整張決標的總額」。
單一標的的案子不加這句(會把「選錯價目表」誤導成「金額沒拆」),已寫成測試。

### ①「費用項目要有公式」②「總計沒算出數字」→ **舊檔,現行已修**

他看的是 `模板\程式產出結果` 那三份。那是 `e11fcf3`(8/12)**之前**的產物
——**mtime 8/13 是他下載的時間,不是產生的時間**(同 [[three-outputs-reconciliation]] 記的)。

舊檔的樣子:
```
r30 貳 職業安全衛生管理費  E=55047  ← 純值,沒公式
r35 (沒項次沒名稱)        E={ROUND(SUM($F$2:$F$32)*7%,0)}  ← 孤兒公式,飄在空列上
```
現行的元長(project_10)是好的:`E30 =ROUND(SUM($F$2:$F$29)*1%,0)`、
`(合計) 1,091,313` 印得出來,而且 `itemsToOperations` 會 `deleteRows r35 刪 3 列`
把孤兒列清掉。

⚠️ **我在這裡連錯兩次,都是自己製造的**:
1. 先說「列印範圍掉了」——實際七個分頁都在,是我用 `bookVBA:true` 讀導致 Names 不全。
   **讀 Print_Area 用 `XLSX.readFile(f)` 就好,別加選項。**
2. 再說「現行程式碼也寫純值」——實際是我從舊檔讀 items 時**只讀 A~E 沒讀複價**,
   而 `費用項目單價公式` 要用 `複價` 算基數,`base=0` 就整個跳過。
   **餵假 items 給 itemsToOperations 時,複價是必要欄位。**

### ③「每日施工紀錄這個區塊應該固定綠色」→ **真的是 bug,已修(`4f58cba`)**

「綠色」= `E2F0D9`。範本把費用列漆綠,但顏色綁在**固定列號**(r33~r37)。
項目數每案不同,擴列/刪列之後綠色留在原地——元長 33 項時費用在 r30~r34,
綠色還在 r33~r34,**貳/參/肆 沒底色、伍/陸 有**。連數值格式也跟著錯開
(`0.00` vs `0.0000`,正是他貼的那個現象)。

新增 `setRowFill` 指令由系統重畫。三個非做不可的細節:
- **施工列要還原**成 `A~I 無底色 + J~WF 橘色 FBE5D6`(日期欄)。
  項目超過範本容量時走 `insertRowsBelow`,它從最後一列 FillDown、而最後一列是綠的,
  新插的列會全部帶綠,綠色反過來蓋到施工項目上。
- **清除只到 I 欄**:一路清到底會把日期欄本來就有的橘色洗掉,整片變白。
- 指令帶**矩形區域**不是列號陣列:604 欄 × 可能 200 列,逐列下指令就是 200 次 COM 往返。

⚠️ **數值格式的錯開沒有一起修**(他只說綠色)。要修的話是同一個位置。

### ④「N 欄應該有公式列出日期」→ **他說先不要**

範本本身也只有 `N8 =工程基本資料!B8`,N9 以下是空的——**不是被弄丟,是還沒做**。
而 `H3`(畫面上的填報日期)`=N8`,**整份監造報表每一格都靠 `$H3`** 決定顯示哪一天,
所以現在只印得出開工日那一天。要做的話得先問「日期列到哪」與「公式還是固定值」。

## 踩到的坑

- **pg-mem 不支援 `IS NOT DISTINCT FROM`**(本專案已有 `COUNT(DISTINCT)`、`to_char`
  兩處同類註記)。改用 `= $1`,與建案那條路的判準一致。
- `project-routes.js` 原本**沒有** `isIdShape`/`safeResolve`,要自己補
  (isIdShape 是專案裁決「不抽共用模組」的第五份照抄)。
- 測試新增 `describe` 時別忘了 `db._setPoolForTesting(freshPool())` + `migrate()`,
  漏了會掉到真的 PostgreSQL,錯誤訊息是 `password authentication failed`。
