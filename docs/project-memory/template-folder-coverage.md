## 怎麼掃的(這個做法可以重用)

對每份日誌跑**全部**讀取器、只認「有日期且有明細列」的命中。關鍵技巧:
**把 `filetypes` 包一層 Proxy 快取 `extractItems`/`readWorkbook`/`extractPages`**,
同一個檔只真的讀一次,40 支讀取器共用。沒有這層,53×40 次檔案解析跑不完。

## 賜利發的 PDF 版:查證後**不該做**

`工作日誌-元長國小-七月.pdf` 與 `(誤)工作日誌-元長國小廁所-七月.pdf` 是賜利發的
(承攬廠商欄寫著),有文字層,但現有 cilifa 讀取器只吃 .xls。**查證後是嚴格子集**:
- 兩者都 21 天,與 `7月公共工程施工日誌-元長國小廁所(修.xls` **日期集合完全相同**
- PDF **只有第一聯**,明細欄位全空(「申報開工」「塞給水、排水管路」都沒有單位/數量/單價),
  而 xls 版有第一聯+第二聯共 693 列

**寫了只會多一條讀到少八成明細的路徑**,而 registry 是「一 vendorKey 一支」,
加 PDF 分流反而讓 PDF 進來時拿到殘缺結果。skill 那條「同一家兩種載體都要做」的前提是
**另一種載體有獨有的東西**(東震的 PDF 多五天),這裡沒有。

## 工具坑:`data/parser-tools/doc-to-pdf.ps1` 在這台壞的

`$word.Documents.Open($In, $false, $true)` 會噴
`Cannot convert the "True" value of type "bool" to type "Object"`。
**改成單參數 `$word.Documents.Open($In)` 就好**(已實測轉出 9 份中的 8 份)。
沒改進 repo——那支在 `data/`(gitignore)裡,而且我只需要臨時轉檔。
⚠️ 大有國小那份 `.docx` **轉檔失敗**(其餘 8 份都成功),原因未查。
⚠️ 中文路徑在 PS 5.1 下會亂碼,**先複製成 ASCII 檔名再轉**(原腳本檔頭就記過這個坑)。
⚠️ 轉完務必確認 `Get-Process WINWORD` 是 0——實測正常收乾淨,但和 EXCEL.EXE 同樣的殘留風險。
