此前 `hardErrors()` 只認「級別 hard 且狀態 diff」,`missing` 一律放行——**九欄全空也能歸檔**。

## 裁決(問過才定的,不要再自行更動)

1. **必填七欄**:工程名稱、契約編號、契約金額、縣市、契約工期、契約規定開工日、契約規定竣工日。
   **學校與決標日可空**——署名欄校名 21/24(3 份被印章蓋掉尾字)、臺中市格式整份無決標日,
   列必填會讓這些合法文件永遠歸不了檔。見 [[kickoff-vs-award-comparison]]。
2. **無決標公告不得歸檔開工報告表**,訊息要承辦人「以決標公告重新建立工程」。
   連帶**移除手動新增工程**(原本只填 name 就能建案),建案入口只剩決標公告一條。
3. **既有工程補掛決標公告不做**——舊工程一律不管,統一走上傳新增。
4. **開工報告表可覆蓋**(只留最新一份,連舊實體檔一起刪);**決標公告不覆蓋**,
   改成建案時以**契約編號**判重,已存在就擋並回 `existing`。
5. 施工日誌(`submission_history`)**不套覆蓋**:那是逐期累積資料,「只留最新」會洗掉前幾期。

## 實作時撞到的三件事(改這塊之前先看)

1. **工作天案例會被必填永久卡死。** `compareKickoff` 遇到基準=工作天就固定回 `missing`
   且不推導,那個 missing 是**系統自己貼的**,承辦人填什麼都不會消失。解法:
   `compareKickoff(values, award, { confirmed: true })` 時把有值的工作天視為
   **已人工換算的日曆天**照常驗算——確認階段的天數來自畫面上的日曆天欄位(工期I),
   前端對工作天刻意留空該欄,OCR 的工作天數字不會流進去。
2. **「沒有決標公告」與「公告檔讀不出來」不可共用同一則訊息。** 原本 `loadAwardNotice`
   兩種都回 null;擋歸檔之後,後者會叫承辦人去砍掉一個其實合法的工程。已改回
   `{found, award}` 分流。
3. **值域錯誤在 routes 層很難寫出「會失敗」的測試**:金額/工期填錯時同時也會與決標公告
   `diff`,舊行為照樣擋得住。要挑**提示級**欄位(竣工日)的不合法值才測得到這一層。
   同理「工作天可歸檔」也不能只驗 200——舊行為的 missing 本來就不擋,要驗那格是 `match`。

## 卡控清單全貌

必填(A)、跨文件比對(B,既有)、值域(C1 金額須正整數／C2 工期須正整數／C3 竣工不得早於開工／
C4 日期格式與日曆合法性／C5 決標日晚於開工日**只提示不擋**)、前置(D1 無決標公告)、
入口(E1 移除手動新增)。提示級經 `warnings` 回前端,顯示在歸檔成功訊息旁——不回等於沒做。

**那份 `docs/samples/驗證清單/監造報表_施工日誌驗證檢查清單_v1.xlsx` 與本主題無關**:
它 48 條全是施工日誌→監造報表(SP3)的檢查,逐列查過沒有一條提到開工報告表或決標公告。
見 [[supervision-validation-checklist]]。
