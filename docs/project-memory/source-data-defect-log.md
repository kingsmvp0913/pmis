## 為什麼是文件不是 DB 表

這些缺陷是**查證過的事實**,要放得下「兩邊的實際值、在哪個儲存格、
為什麼確定不是讀錯」——那是段落不是欄位。目前只有 6 筆,做 DB + UI 是過度設計。
文件在 repo 裡,下個 session 與 code review 都看得到。
**要等到承辦人真的需要在畫面上看到「這個硬錯是已知的」才做 DB 表。**

## 收錄標準(寫在文件開頭,這裡只記重點)

只收**逐格查證過、確定不是讀取器讀錯**的。判準:讀取器讀到的值 = 文件上印的值,
而該值與另一份文件對不起來。**不收「還沒查清楚」的**——那會讓下一個人以為
查證過了,比不記更貴。文件裡義賢那筆刻意標了「尚未查證」當反例。
