2026-08-05 完成 SP2(發包經費總表 → 契約詳細價目表)。以下每一條都是實測,
不是推論;要再動抽取或寫入規則前先讀這篇。權威規格見
`docs/superpowers/specs/2026-08-05-SP2-契約詳細價目表-design.md`。

## 挑表:分頁名稱完全不可靠

**5 個檔案(南陽、新光、東榮廁所、重興廁所、重興汙水)的第一張詳細價目表,
施工小計全都是 1,185,308**——那是南陽的數字,這些檔都是拿南陽那份改的,
第一張是沒改乾淨的殘留。照分頁名稱挑會 100% 挑到錯的那張,而且錯得看起來
完全正常(版面、項目數、格式都對)。

唯一客觀判準是**決標金額**:30 份有明細的樣本,施工項目 + 費用項目的複價和
= 表上「發包工程費合計」= 決標公告的契約金額,無一例外。搜尋限制成「每個檔案
至多取一張」(同檔兩張是舊版與新版,相加無意義);跨檔相加是真實需求
(重興:廁所 871,943 + 汙水 812,102 = 1,684,045)。

分頁命名有 6 種變體(`詳細價目表`/`詳細預算表`/`詳細表`/`(標單)詳細價目表`/
尾端帶空白/`(2)`),故判定改用結構特徵:**A 欄為阿拉伯數字且有單價的列數 ≥ 3**。
實測分離乾淨——詳細價目表 6~34 項,經費總表恆為 2 項(柒工程管理費下的
學校/縣府管理費)。

### 項次會帶子工程前綴(2026-08-08 補,commit `1abe405`)

**一份經費總表可以含兩個子工程**(古坑:A 棒球場圍籬 / B 車棚),項次因此長成
`A.壹.1`、`A.貳`。原本只認純阿拉伯數字或純中文大寫 → **整份收 0 項、候選 0**,
SP2 卡在「選不出契約詳細價目表」,整案做不出報表。判定改看**以「.」切開的最後一段**。

- 「壹 是大類標題不收」的意圖自動保持:`A.壹` 的最後一段就是「壹」。
- **放寬前一定要先離線比對全部案子**:實測 45 案裡只有古坑一案結果改變,
  其餘 44 案逐分頁的項目數完全相同 —— 沒這個比對就不敢在跑批次時動 production。
  比對腳本的寫法:把新舊規則各實作一份跑同一批檔案,比 `分頁名:項目數` 的簽章。
- 影響面就這一案(49 案掃過),但這是**整案卡死**型的失敗,不是少讀幾項。

## 寫入:兩個分頁的規則不一樣(初版在這裡錯了)

38 份已填實例釘出來的:

1. **監造報表引用列數 = 價目表項目數 − 5**(豐榮 39→34、南陽 36→31、
   東榮災後 11→6)。差的是五個費用項目——那個分頁給人看施工進度,
   職安衛管理費與營業稅沒有施工進度可言。每日施工紀錄則收全部項目。
2. **監造報表的項目區正下方就是報表正文**(二、監督…/三、查核…/簽章)。
   `copyRowDown`(FillDown)會直接覆蓋掉,**而且沒有任何錯誤訊息**,產出的報表
   看起來只是「少了幾段」。豐榮實例的正文在第 44 列,正是被往下推 3 列的結果。
   SP0 為此新增 `insertRowsBelow`(先 Insert 推開再 FillDown)。
   每日施工紀錄第 38 列起本來就空白,FillDown 無妨。

**這兩個錯是「真跑一次 Excel」才發現的,單元測試全綠**——mock 測不出
FillDown 覆蓋了什麼。動到擴列邏輯後務必再真跑一次(見
`tests/template-engine.integration.test.js` 的 insertRowsBelow 那支)。

## 其他實測數字

- **複價恆等於 `ROUND(數量×單價)`**:1094 列全部符合。故交給範本 F 欄公式重算
  不會有差額,而對不上就代表檔案被人改過(列為硬錯)。
- **費用項目不限五個**:多數貳~陸,四湖跳遠有到玖共 8 個。規則不可寫死 5。
- **1 份完全沒有明細**(臺中市大勇紅磚道):只有經費總表與預算總表,兩者都只到
  「壹 直接工程費」大類。這種檔案建不出價目表,要明確擋下並說明。
- **項次照原樣保留**(`1`..`N`、`貳`..`陸`):施工日誌讀取器解出來的就是這個形式
  (`parser-jinda.test.js:56,88`),重編號會讓 SP3 的契約表核對全部對不到。

## fixture 做法

`docs/samples/` 的 xls/xlsx/xlsm 不版控,故測試 fixture 由
`scripts/make-budget-fixtures.js` **從實檔產生**,8 份各代表一種樣態
(雙表殘留、跨檔合併、8 個費用項目、39 項擴列、完全無明細、子工程前綴)。
要加新樣態:把實檔複製進 `docs/samples/發包經費總表/` → PICK 加一行 → 重跑腳本。
**重跑會覆蓋全部 fixture,跑完用 `git diff` 確認既有的沒變**(實測是零差異;
若有差異就代表來源檔或 SheetJS 版本動過,不可直接 commit)。
不手打——SP1B 手打過的 fixture 讓規則永不觸發卻全綠(見 [[sp1b-ocr-geometry-findings]])。
