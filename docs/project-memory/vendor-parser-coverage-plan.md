## 待做：**清空**（2026-08-08）

原始 34 案 / 24 家全部補完。最後一家宏恩用「先轉 PDF」解掉，作法如下。

### 宏恩：.doc 的解法（已採用，commit `12b3c3f`）
- 唯一那份日誌是 `施工日誌(更).doc`，實測是**真的 Word 97-2003 二進位檔**
  （magic `D0CF11E0`、內含 `WordDocument` 串流；SheetJS 開它會說 Cannot find Workbook stream，
  所以不是「副檔名寫錯的 xls」）。
- 粗掃 UTF-16LE 看得到內容確實是標準公共工程施工日誌（工程名稱、承攬廠商、
  本日/累計完成數量等欄位都在），**但取不到表格結構**——Word 二進位把欄界放在
  格式串流裡，硬從文字流猜欄位就是編造。
- **採用第三條路**：用 Word COM 另存 PDF（`SaveAs2($path, 17)` = wdFormatPDF），
  轉出來有完整文字層與座標，再走既有的 `extractItems`。腳本收在
  `data/parser-tools/doc-to-pdf.ps1`。**中文路徑在 PS 5.1 會亂碼**，先複製成
  ASCII 檔名再轉（同 [[sp4-official-doc-findings]] 的結論）。
- **讀取器收到 .doc 會 throw 並在訊息裡講要先轉 PDF**（不可回空陣列）。
  作業上要有人先轉檔再上傳；案資料夾裡目前仍只有 .doc（沒有動使用者的樣本資料）。
- Word 轉出的 PDF 有三個特有的坑（都寫進讀取器檔頭）：數字被切成好幾個 item
  （「115年1月28日」= 七個 item）、進度的值與標籤不同帶、段落標題會被併進最後一列的名稱。

## 宜謙（已完成 `e067271`，以下是版面事實，要改讀取器前看這裡）

- **檔名帶「掃描」的是無文字層掃描件**（實測 extractPages 回 0 字元），一律讀不了；
  同期間通常有另一份 A 版（`0601A-0630A.pdf`）是有文字層的，優先用那份。
- **有 .xlsx 版**（`0923A-0930A.xlsx`、`1001A-1031A.xlsx`）：單一分頁 `Table 1`，
  一天一組區塊往下堆（3157 列 / 31 天），版面與 PDF 完全相同（同樣兩聯）。
  ⚠️ 上一版記憶說「名稱多一個『產品，』前綴，PDF 版沒有」是**錯的**——PDF 版也有，
  只是全形逗號。兩邊 NFKC 後同字。
- **進度欄的載體不同**：PDF 印「0.34 %」（已是百分數）、Excel 存 0.0034（分數，
  儲存格格式才是 %）。混著收會差 100 倍，依型別分流。
- 實測 **31 份裡 17 份讀得動**（4 案）：其餘是 7~68MB 掃描件；11301 忠信兩份全是掃描件。
  （commit e067271 的訊息寫「14/25」是憑記憶的舊數字，實際重數是 17/31。）
- 「二、工地材料管理概況」那張表**366 天全空**（不是沒讀）。
- **PDF 版一天兩頁**：頁 1 第一聯（header／出工／機具／材料，施工項目只列當天有施作的），
  頁 2 第二聯「完成工程詳細表」＝完整明細。**兩聯都沒有單價與金額** → 那兩欄只能 null。
- **項次三層**：壹（大類）→ 一/二/三（中類）→ 1..N，**每個中類各自從 1 編號**，
  前綴成「一.1」「二.1」——但**只前綴中類、不前綴大類**（招式 15）。
- **金大讀取器是假陽性**：讀得出 44 天/1364 列，但 D1「同一天出現兩次」＋ E4/E5/E6
  一堆（單價讀成 2、數量 0.05），值是錯位的。不要沿用。
- PDF 的**數值右對齊、表頭左對齊**，用表頭欄界 `[x, x+w]` 判定會全部落在界外；
  改用「以各表頭的起點 x 為分界」的區間法（實測第一聯與第二聯都成立）。

## 一支讀取器的固定作法（10 家都這樣做，直接照抄）

1. `node step0.js "<廠商名>"` → 列出各案樣本 + 拿現有每支跑一遍（第 0 步）。
   **看「天數/列數/有名稱數/日期範圍」判斷是不是假陽性**：日期全 null、
   或只讀到個位數列，都是碰巧命中錨點而已。
2. `dump-xls.js`（分頁清單）→ `dump-compact.js <檔> <分頁> <起> <迄>`
   （合併填充後同值連續欄很多，compact 版只印「值變化處」，比 dump-xls 好讀太多）。
3. 寫 `<key>.pmisparser.js`，selfTest 用**真實座標**（只換工程名稱），
   每一條斷言都對著一個「錯了不會有欄位變 null」的坑。
4. `batch-check.js <key> <案資料夾…>` → 缺漏/名稱異常/硬錯全 0 才算過；
   不是 0 就逐條 `show-errors.js` + `raw-day.js` 溯源到原始格。
5. fixture 挑**最小但涵蓋該案特徵**的一份，寫 `parser-<key>.test.js`
   （含 `registry.inspect` 的安裝路徑測試——晉林那個「只在安裝時發作」的 bug 只有它抓得到）。
6. commit 訊息寫**為什麼**（那個坑長什麼樣、不修會怎樣），不要寫「新增 X 讀取器」。

## 通用招式（下一家直接套）

1. **「還沒填的天」一定要濾掉**，否則 SP3 噴一整片 A1/A2 把真問題淹掉。
   廠商都是把整個工期的區塊一次建好再逐日填。判定要**兩個條件並用**：
   「沒有日期（或沒有天氣）」**且**「整天沒有任何本日完成量（null **或 0**，
   金額欄是公式，沒填時算出 0）」。只用前者會讓真的漏填的日子靜默消失。
   濾對了的佐證：**天數會止於檔名日期**（20251117 → 11/17）。
2. **項次撞號 / 沒有項次**：沒有項次欄就用「排除大類後的出現序」（位置事實，
   不是推導數值），已用人工監造報表的契約詳細價目表驗證過逐項同序；
   多張表各自從 1 編號時要前綴大類（一.1 / 二.3）。
3. **大類的判定用「單位欄為空」**，不能用「項次非數字」——費用項（貳~陸）的
   項次也是中文數字，但它們有單位有單價，是真項目。
4. **單位一律白名單 + NFKC**（全形 ㎡ 折成 m2 才對得上 SP3 的單位字典）。
5. **進度取「累計」那一組**（很多格式本日/累計都有），SP3 的 F3/C4 驗的是累計語意。
6. **金額欄不照標籤收**，要用「單價 × 數量」交叉核對；沒有的就 null 不回推。
7. **讀不動的檔要 throw，不可回空陣列**——回空會被上游當成「這份沒有資料」靜靜略過。
   掃描 PDF 餵給 SheetJS 會回一份空活頁簿。
8. 交付前一定跑 scratchpad 的 `batch-check.js <key> <案資料夾…>`：一次看
   天/列/缺漏/名稱異常/硬錯碼；**硬錯逐條溯源，多數是廠商自己的資料錯**
   （契約變更改單價、修訂版把欄位貼錯位、單日漏填天氣）。
9. **同一家不同案、甚至同一案不同版本，欄位語意會不一樣**。正郁兩案的金額欄
   一個是本日、一個是累計；中和早期版本的單位欄整排貼錯位。
   → 語意有疑慮時**用算式在整份檔案上統計命中率再決定**（見 zhengyu 的
   `detectAmountMode`），判不出來就 null，不要挑一個看起來合理的。
10. **單日列印範本 ≠ 資料來源**。聖隆/尚仁/惠晟的活頁簿裡都有一張用公式抓「當天」
   的漂亮表單，逐日資料其實在矩陣分頁。挑錯來源只會讀到一天。
   而且那種範本的抬頭常是**別的案子的殘留**（尚仁的第二聯寫著桃園市政府）。
11. **多張分頁/多個檔會重複**。月份分頁互相涵蓋（正郁）、累積式檔案（經緯 14 份
   都是同一個工程的快照）。依填報日期去重，並確認輸出照時序排序。
   久木更極端：6 份 xls 是同一個工程的逐月快照，10 月檔一路含到 5/31（169 天裡
   144 天跨檔重複），而且分頁在檔案裡**倒序**排列（6(30) 在最前）。
12. **Excel 合併填充後「整列皆空」永遠不會成立**（那是 grid 而非原始格）。
   拿它當區塊結束條件，會一路吃到分頁末端——久木的材料區因此把整個第一聯的
   安衛檢查事項都收成材料。**用段落標題／下一個表頭當界**。同理，表頭上一個
   合併 6 欄的標籤會被當成 6 個獨立區塊，同一筆資料收 6 次：先把表頭列壓成
   「連續同值只留最左欄」的分段再用。
13. **單檔跑 SP3 時 B3/F4 大量硬錯，先確認是不是「缺前期累計」**。逐月檔的第一天
   帶的是前面幾個月累積出來的累計數量，而本檔內只累加得到當月金額，必然對不上。
   佐證方法：含開工日的那一份會是 0 硬錯；把全部檔案依日期去重合併後再驗一次。
   久木實測：單檔 157~762 硬錯 → 合併 169 天後 0。
14. **有真實發包經費總表時，拿 SP2 讀出來的契約表當基準，別拿人工答案卷**。
   答案卷的項次是人工加過大類前綴的（壹.1），用詞也與日誌不同，會生出一整片
   E1/E3 假警報（久木實測 E1 硬 18／軟 378、E3 軟 72）；換成 SP2 從
   `發包後經費總表` 讀出的 27 項後全部歸零——那才是 pipeline 實際會比對的東西。
   `budget-sheet.js` 的 `findCandidates` 只回名稱，rows 要自己從 `readSheets` 取。
15. **要不要加大類前綴，看發包後經費總表怎麼編號，不要憑感覺**（宜謙實測）。
   同一家 4 案：石榴／饒平的日誌沒有中類、項次就是 1..N，與經費總表逐項同號，
   加了「壹.」會每天每列噴 E1；鎮西／棒球場有中類（一/二/三各自從 1 編號），
   不加前綴則同一天出現三個「1」，SP3 以項次為鍵的 prevCum/dailySum 會把三個
   不同項目的累計混在一起。規則：**大類（壹貳參）不當前綴、中類（一二三）才當前綴**、
   費用項（貳~陸）本身是頂層編號不加前綴。
   ⚠️ 副作用要知道：`是費用項目 = !/^d+$/.test(項次)`，一旦前綴成「一.1」，
   B2/F1/B3 就從硬錯降成軟警告。有中類的案子等於少了三條硬把關，這是取捨不是 bug。
   ⚠️ **經費總表自己也會重編號**（鎮西 A 檔 = 一13項+二12項+費用5項），
   於是 SP2 的 `validateItems` 會判「項次重複」擋下來——那是 SP2 層要解的，
   不是讀取器。量測時用 scratchpad 的 `check-sp2-prefix.js`（照同一規則替契約表補前綴）。
15b. **「表報編號：」是工程會標準表單的共通錨點，至少 8 家在用**（利成/德信/沅隆/
   優和/以勒/義鼎/東震/齊全…）。只靠錨點會**假陽性**：讀得出一堆天、每一天卻都是空的。
   每一支用這個錨點的讀取器都要加一道「全部讀不到填報日期就 throw」的防線
   （實測齊全的檔會被利成的錨點吃下去，回 94 個空白天）。
15c. **項次要用「出現序」還是「名稱」，數一下「總明細列數 ÷ 天數」就知道**：
   每天都印完整清單的（德信 18/天、以勒 9/天、東震 25/天）用出現序，與經費總表逐項同序；
   逐日只列當天施作的（利成 153 天只有 113 列、沅隆 64 天 62 列）**一定要用名稱**——
   出現序在跨天/跨檔時會指到不同項目，而 SP3 以項次為鍵，會把兩個項目的累計混在一起
   （實測沅隆 B2:45、E4:16、E5:18，改用名稱後歸零）。
15d. **PDF 的跨行名稱：數值印在整塊名稱的垂直中央**（沅隆實測四行名稱、數值在頭尾中點）。
   用「離最近的數值列」會把名稱接到隔壁項目上。做法：數值列自己那行沒有名稱時，
   **一次收一上一下**對稱擴張；「自己那行就有名稱」的列不參與收編，否則它會來搶。
15e. **出工/機具那組欄界一定要包含「累計使用數量」**，否則最後一格從「本日使用數量」
   一路吃到列尾，本日 1 與累計 1 會變成 11（東震實測，同一天的 xls 與 PDF 因此對不起來）。
15f. **範本/複本分頁會帶著真日期**（利成 `12月 (3)`、以勒 `可改`、優和多份檔重疊）。
   依填報日期去重、**保留明細多的那一份**；不做的話 D1 一片，累計還被算兩遍。
16. **一家可能有兩種載體（PDF + xlsx）而版面相同**。分流只在「怎麼取到一列」，
   欄位規則要共用一份，否則兩條路的輸出語意會漂（宜謙的進度欄就是：PDF 百分數、
   Excel 分數）。`parseAll` 依副檔名分流，兩條路都要進 selfTest。

### ⚠️ 兩個「我自己的統計方式製造出來的假象」(做這類表都會踩)

1. **零列會拿滿分**。三道關卡全是逐列檢查,`allRows.length === 0` 時每一關自動過。
   優和第一版就被判成「45 天 / 0 列 / ✓ 通過」。**沒有明細一律先判 `✗ 沒有明細`。**
2. **「明細列」與「受檢列」必須分開報**。受檢列 = 扣掉 `isCategoryRow` 之後的。
   優和的來源**只有名稱、整份沒有任何數量欄**,全部被濾掉 → 受檢 0 但明細其實有 41 列。
   只報後者會看起來像讀取器讀不到東西。

### ⚠️ 這張表的「SP3 硬錯 0」不等於這家沒問題

預設是**自我基準**(拿日誌自己第一次出現的值當契約值),讀取器若每天都用同樣方式讀錯,
自我比對永遠一致——富森就是這樣過三關的。要抓系統性讀錯得 `--contract <工程id>` 接外部基準。
同理,表回答的是**「當初驗到什麼程度」,不是「這家所有檔案都讀得動」**(樣本只有 fixture)。
