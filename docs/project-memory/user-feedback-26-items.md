## ⛔ 第 26 項:「每家格式不同也能吃」是**我誤解**的需求

這一列原本記著「他要的是每家格式不同也能吃」,並掛著 🟡 未做。
2026-08-15 向承辦人解釋這一項時,他直接回:**「監造報表的最終格式都是統一的」**。

實測驗證(沒有用猜的):把模板資料夾裡**全部 98 份**監造報表餵進 `report-verify.js` 的
`verifyWorkbook`,**98 通過 / 0 不通過**。其中 39 份在 `模板\監造報表\`——
那正是「監造方做好的」那一批。

📌 教訓:**「支援各家不同格式」這種需求聽起來合理,但要先確認它真的存在。**
我差點為此設計一套「上傳空白樣板 → 標出欄位落點 → 人工確認」的機制,
而那是寫入路徑(認錯欄位會把數字寫進錯的格子且看起來完全正常),
是這個專案裡最危險的一類改動——為一個不存在的需求。
