2026-08-11。使用者要「打開一份新產出的報表看一眼」時,我先以為只有他做得到。
**其實可以自己看**:Excel 匯出 PDF → pdfium 轉 PNG → 直接讀圖。
第一次這樣做就抓到**三個逐格比對永遠看不到的缺陷**,而在那之前
儲存格的值與版面屬性(`!ref`/合併格/欄寬/列高/隱藏列/邊界)已經全部對齊了。

## ⚠️ 教訓:比對儲存格 ≠ 看報表

抓到的三個(都在 `bf718d2`):

1. **`########`** — 契約數量欄。值是 2600 沒錯、格式 `#,##0.00` 沒錯、欄寬 9.89
   也與人工報表一致,就是放不下「2,600.00」。**儲存格層完全正常。**
   人工報表的做法是把那一欄拉寬(49 份實測 9.67~13.00)或少用一位小數。
2. **「預訂完工日期」比開工日還早** — 決標公告讀不到契約工期時 `B8+B7-1`
   算出「開工日 − 1」,一個看起來合法的日期。
   ⚠️ **有兩個地方各算各的**:`工程基本資料!B9`,以及監造報表實際印的那格走
   `G5 → 監造內容!P 欄 = $B$8+$B$7+$L#+$M#-1`(還多加展延與停工天數)。
   **只改 B9 印出來完全沒變**——找的時候要從印出來的那一格反推,不要從欄位名猜。
3. **該有文字的地方印出一個裸的 `0`** — 「四、督導工地職業安全衛生事項」。
   `監造內容!H3 = IF(Q3>1,$R$3,$R$4)` 而範本的 R3/R4 是空的 → 取到 0。
   49 份人工報表這兩格**一字不差**,是固定文字。與 `C2`/`D2` 的「上午/下午」、
   A 欄表報編號、進度統計列標籤同一類:**範本被清空時把該留的一起清掉了**。
   看到報表上出現孤零零的 `0`,先去找它引用的那格是不是被清空了。

## 怎麼做

```
node <scratchpad>/topdf.js  <xlsm> <分頁名> <out.pdf>     # 走 export-sheet-pdf.ps1
node <scratchpad>/pdf2png.js <pdf> <前綴> 1500 1          # 1500px 寬、只轉第 1 頁
```
- 匯出用 `data/parser-tools/export-sheet-pdf.ps1`(`ws.ExportAsFixedFormat`,
  沿用 excel-com-driver 的 COM 重試與 kill 收尾)。
- **`pdftoppm` 沒裝**,別走 Read 的 PDF 直讀。改用專案已有的 `@hyzyla/pdfium`。
- ⚠️ **`canvas` 沒裝**(OCR 那條路的選配依賴),所以 PNG 要自己編:
  PNG = 簽章 + IHDR + IDAT(zlib deflate 掃描線,每列前面補一個 filter byte 0) + IEND,
  用 Node 內建 `zlib` 即可,約 20 行。
- ⚠️ **pdfium 給的是 BGRA,PNG 要 RGBA**,不換通道整張圖藍紅顛倒。
- 需要 `NODE_PATH=C:/pmis/app/node_modules`(腳本放 scratchpad,不在 app 底下)。

## 第二輪:契約詳細價目表(2026-08-11 稍晚)

只補到一個真缺陷:**合計列的「(合計)」標籤**(範本 B283 空白,49 份人工報表全部有)。
藍底列只有右邊一個金額、左邊空著。修法別寫死列號——刪列之後會變,改用
「F 欄是 `ROUND(SUM(F2:F…))` 的那一列」去找(`d0a38ea`)。

⚠️ **兩個「看起來像 bug 但不是」,別再追**:

1. **長名稱換到第二行被列高切掉**(壹.1/壹.2/壹.8/壹.10/壹.12/壹.15/壹.21/壹.22)
   ——**人工報表一模一樣被切**。那是他們一直以來的樣子。**修了反而不一樣。**
2. **契約數量欄:人工印出 `#######`,系統印出 `2,600.00`**——這一欄**我們比他們好**
   (autoFitColumns 的功勞)。不要為了「跟人工一致」把它改回去。

👉 **教訓:看到差異先問「人工那邊長怎樣」,不要預設系統就是錯的那一方。**
**六個分頁都看過了**(監造報表/契約詳細價目表/封面/每日施工紀錄);`監造內容` 與 `封面 (2)` 還沒。

## 第三輪:封面 + 每日施工紀錄(2026-08-11 收工前)

**封面**——抓到範本一個真 bug:
`封面!A28 = "中 華 民 國 "&YEAR(TODAY())-1911&" 年 "&MONTH(NOW())+1&" 月"`
——月份是**今天 +1**。八月印「9 月」,**十二月印「13 月」**。
⚠️ **49 份人工報表裡 35 份仍在用這條公式**,所以這個錯真的印了很多份。
改成 `MONTH(TODAY())`(`0f7d679`)。順帶補封面的「期別」行(`A16`,49/49 都有值、範本空白)。

**每日施工紀錄**——抓到**我自己造成的迴歸**:`autoFitColumns` 把 H(累計完成金額)
從 10.67 撐到 13.33,多出來的寬度把最右邊的**「完成百分比」整欄擠出列印範圍**
(連表頭都不見,底部五列進度標籤也被切成「每日1」「總1」),**而儲存格的值全是好的**。
根因是我把 autofit「順便」推到另外兩個分頁——**那是推測,沒有觀察到病徵**。
收回到只 autofit 監造報表 H/I/J(`0073896`)。

👉 **教訓:版面的順手優化要有觀察到的病徵才做。** 加寬一欄是零風險的直覺,
實際上會把別的欄推出紙外——而且只有印出來才看得見。

## 第四輪:監造內容 + 封面 (2) —— 六個分頁全部看完(2026-08-11)

**監造內容**:`E3`(第一天的「一、工程進行情況」)在範本裡是 solid `FFFF00` 填色,
同欄其餘都沒有,49 份人工報表 48 份無填色——**編輯範本時標記後忘了清掉**。
每份產出都印出一格黃底。清掉(`70eff67`,驅動 `clear-template-fill.ps1`)。
與 `監造報表!N8` 寫死 46203、價目表的驗算草稿公式同一類殘留。

**封面 (2)**:沒問題。「監造單位：」空白不是缺陷——那一欄來自事務所設定,
`build-and-compare` 刻意不帶(它的 `NOT_IN_AWARD`),實際流程會填。

### 範本殘留的完整清單(同一個模式,已全部清掉)

| 殘留 | 症狀 |

| `監造報表!N8` 寫死 46203 | 35 個 #N/A |

👉 **看到「範本某格空白但 49 份人工報表都有」就是這個模式**,直接補。
反過來,**看到「系統有而人工沒有」先懷疑是範本殘留**。
