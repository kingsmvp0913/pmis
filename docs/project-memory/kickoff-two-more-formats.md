## 一、敘述式開工報告書(寶嶸,`[開工報告]函+[開工報告].doc` 頁 3)

守門放行後只讀到 2 欄(契約工期 180 日曆天、開工日 2026-07-15),**兩個值都對**。
其餘 7 欄 null 的根因是**這是另一種格式**——不是表格式,是敘述式:

```
行1  雲林縣麥寮鄉橋頭國民小學
行2  工程開工報告書
行3  工程名稱木                          ← 標籤格被 OCR 污染成「工程名稱木」
行4  橋頭國小暨許厝分校114-116年…整修工程  ← **值在下一行,不在右邊**
行5  案號或契約號碼                       ← **這個標籤 LABELS 沒有**
行6  A1150507
行7  工程開工日期
行8  本工程自 115年 7月15日正式開工。      ← 退路句,開工日靠它抽到 ✓
行10 （工期：180日曆天，完工限期為116年1月10日）  ← 工期抽到 ✓、**竣工日沒有**
```

三個各自獨立的缺口:
1. `LABELS.契約編號` 只認「契約編號」,這份寫**「案號或契約號碼」**。
2. **值在標籤的下一行**,而幾何配對找的是「標籤右側、垂直帶重疊」——這種
   上下排列的敘述式版面配不到。加標籤沒有用,要先解決配對方向。
3. 竣工日埋在「完工限期為116年1月10日」這句裡,沒有獨立標籤,要退路句。

⚠️ **不要只加標籤就宣稱修好**——加了 `案號或契約號碼` 之後,值(行6)仍在下一行,
幾何一樣配不到。要驗證就得真的再跑一次 OCR。

## 二、中文大寫金額(義賢,`義賢國小廁所_開工報告表(日期有誤).pdf`)

契約金額整格讀不到的根因抓到了。OCR 原文:

```
行6  契約金額
行7  契約編號YSPS1150702
行8  仟貳佰零陸元整          ← **中文大寫金額,而且只讀到尾段**
```

前段(百萬/十萬位)整段沒讀到。`isPlausibleValue` 對含國字大寫的值是放行的,
所以擋掉它的是 `parseMoney` 解不出殘缺的大寫串——**回 null 是對的**
(硬解會生出一個看起來合理的錯金額)。

**這就是使用者清單第 16 項「中文大寫金額難讀取」的實證。** 真正的問題不是
「大寫難解析」,是 **OCR 把大寫金額串讀漏了一半**。要改善得從 OCR 那一層下手
(解析度、或針對該區塊重掃),不是去改 `parseMoney`。

### ⛔ 上面那份 2026-08-13 的診斷有兩處是錯的,別再照它修

1. **「中文大寫金額 OCR 只讀到尾段」——現在兩段都讀到了。** 義賢的
   `新臺幣貳佰柒拾參萬玖` + `仟貳佰零陸元整` 都在,只是被斷成上下兩格。
   **根因不在 OCR 層,在解析層**,三個各自獨立:
   - `新臺幣` 前綴被 `cnNumToNumber` 當成雜訊而整串放棄(那條「不認得就放棄」
     的規則是對的,但前綴不是雜訊)。
   - 兩格沒接起來。**行層接不起來**——中間夾著「契約編號」那一行;
     但**座標上正上下相鄰**(豐榮 x503/x500 間距 5px、義賢 x772/x769 間距 20px)。
   - **退路的觸發條件錯了**:原本「標籤沒命中才走退路」,而標籤路徑會抓到被切斷的
     前半段(非 null)→ 退路整個被擋掉。改成「**解不出金額**才走退路」。
2. **「值在標籤的下一行,幾何配對配不到」——版面其實是標籤左、值右。**
   那個結論是被 OCR 的**閱讀序**誤導的,看座標就知道。真正的缺口是
   `valueFor` 的 `if (f.rest) return take(f.rest)` **短路**:標籤格尾巴沾到雜訊
   (「工程名稱木」)時,餘文過不了型別把關就整欄結案,不再往右找。

### 📌 一個會反覆出現的陷阱:被切斷的大寫金額

豐榮只拿到前半段「新臺幣參佰貳拾伍萬壹」時,硬解會得到 **3,250,001**,
真值是 **3,251,769**——看起來完全合法,比對層與承辦人都看不出來。
守門判準用**國字大寫的慣例**:跳位要用「零」補(…貳佰**零**陸),
所以「萬」後面直接接一個數字又是最後一個字 = 單位被切掉了 → 回 null。

義賢 9/9 全讀到;工期讀到之後,那份「竣工日填錯」的案子會報成
「120 vs 表內推導 106」——正好指到問題點(正確的 11/27 推導剛好 120)。
