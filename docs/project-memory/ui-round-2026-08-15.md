`white-space: normal; overflow-wrap: anywhere`。使用者下一張截圖就出現

📌 **短標籤與長訊息要分開處理,不可以一律 nowrap**:同一張表的「說明」欄與
開工報告表的「結果」欄裝的是整句話(「工作天,單位不同無法比對,請自行核對填寫」),

## 自動關窗的判準(現在跨三處一致)

**歸檔/寫入成功就關掉彈窗,但「有東西要承辦人回頭處理」時不關。**
關掉等於把那段訊息丟掉,而動作已經成功、他不會再打開這個彈窗。

- 開工報告表(`71115d2`):`onArchived({ warnings })` → 有 warnings 就不關
- 契約詳細價目表(`a2916fb` + `2d87c19`):`onWritten({ warnings: 缺欄位 })` 同一套
- 兩者共用 `projects.js` 的 `done`,判準只寫一次

⚠️ 提示級的東西**刻意不用 toast**(會消失),而是留在卡片上。這是既有裁決,
不要為了「畫面乾淨」改掉它。

## 「後端回了、前端沒用」是一類缺口

`contract-items/confirm` 一直回著 `基本資料: { 已寫入, 缺 }`,後端註解還寫著
「不講的話承辦人無從得知那一頁是不是滿的,而空著的後果要到印出來才看得見」
——**而前端從頭到尾沒有顯示它**。`2d87c19` 補上,並讓後端一併回 `缺欄位` 名單:
只給數字承辦人還是不知道要去補什麼。

📌 值得順手掃一遍其他路由:**回應裡帶了、畫面上卻找不到的欄位**都是同一型。

## 工程列表的狀態篩選與排序做在前端

`status` 是後端**推導**的(`deriveStatus` 看實際竣工日與開工日),不是 projects 的欄位。
為了一個推導值去改 SQL,會讓那條查詢多背一份狀態邏輯,兩邊定義一漂就會出現
「列表說施工中、詳細頁說已竣工」。

三個刻意的設計:**預設仍是後端順序**(事務所編號 ASC NULLS LAST)、**點第三次回預設**、
**空值一律排最後不隨升降序翻**(否則設計費降序時一整片「—」擠在最前面)。
狀態照工程時序排(未開工→施工中→已竣工),字面排出來是「已竣工/未開工/施工中」,
對承辦人沒有意義。

📌 名稱排序走 `localeCompare('zh-TW')` = **筆畫序**(乙1畫→丁2畫→丙5畫→甲5畫),
符合台灣慣例。第一眼會以為壞掉,不要「修」它。

## ⚠️ `contract-items.js` 裡有 null byte,grep 會把它當 binary

`app/public/js/views/contract-items.js` 有 **2 個 `\0`**——那是**刻意的**,
拿來當複合鍵的分隔符(`${m.file}\0${m.name}`,檔名不可能含 NUL 所以安全)。
後果:`Grep` 工具回「binary file matches」、看不到內容。
**用 `tr -d '\000' < 檔案 | grep …` 或 Read 工具。** 不要以為檔案壞了
(git 乾淨、`node --check` 過)。

## 前端驗法的補充

[[working-environment]] 記的覆寫 Api 那招照用,但這一輪多兩個教訓:

1. **要驗「彈窗會不會自己關」就一定要走真正的 `openFlow`**(點列表上的流程鈕)。
   自己 `modalDialog(...)` + 自己的 callback 只驗到 payload,關窗邏輯在
   `projects.js` 的 `done` 裡,完全沒被執行到。第一次就是這樣白驗一輪。
2. **`javascript_tool` 每次呼叫是獨立的執行環境**,上一次宣告的變數不存在。
   要跨步驟就掛 `window.__x`,或整段一次跑完。

⚠️ 另外:契約價目表那個彈窗有一道真實閘門(**合計 ≠ 決標金額就不顯示寫入鈕**)。
用 JS 點隱藏按鈕會繞過它——驗到的是 handler,不是閘門。**報告時要講清楚差別。**
