## 已拍板並實作:工作天的完工期限(2026-08-10)

使用者的回答是「**只需要驗算,前面辨識到的完工日是算好的**」——開工報告表上本來
就印著契約規定竣工日(23/23 讀對),系統不必自己算。因此:

- **工期自洽性檢查改判準**:工作天與日曆天不是同一個單位,不要求相等;工作天扣掉
  假日必然 ≤ 同期間的日曆天數。100 工作天配 167 日曆天合理,100 工作天卻只有
  80 日曆天就是這份表填錯。⚠️ 這同時修掉一個迴歸——工期天數與基準拆成兩欄之後,
  舊的「確認階段必是人工換算後的日曆天」前提不成立,工作天的案子會被擋到歸不了檔。
- **B9 不再覆蓋工作天案子的主檔竣工日**(B9 = B8+B7-1 是日曆天算法)。

沒有走「系統自動算工作天完工日」:WORKDAY 只排除週六日,國定假日要另外維護一份
每年更新的清單;而營建的工作天還要扣雨天等不可施工日,那是現場認定的。算出來的
永遠是下限,不如不算。

## 第 5 項的三個實作決定(踩過才知道的)

1. **公式格不算「已填」。** 反過來做過一次:公版範本的每日施工紀錄光公式格就有
   6074 個(第 1 列日期公式鋪到 ACH、合計列、第 33 列自己 506 個),當成已填的話
   上傳一份幾乎空白的報表就保護 6387 格,SP3 之後**寫不進去而且完全看不出來**
   ——承辦人看到「已寫入」成功訊息,報表卻沒變。改掉之後同一份是 58 格。
2. **保護靠切開範圍,不是寫回原值。** setRange 是整塊 Value2 寫入,把原值讀出來
   填回去會把公式壓成死值。改成逐列切成不含保護格的連續區段。
3. **三條寫入路徑都要過 `applyProtection`**(SP1/SP2/SP3),漏一條那條就能蓋掉
   已填內容。刻意不做進 template-engine——那是通用 Excel 工具,不該懂業務概念。

## 舊的待拍板紀錄(保留出處)

第 2 項做完後留下的洞:範本 `工程基本資料!B9 = B8+B7-1`,那是**日曆天**算法,
選工作天時會算出偏早的完工期限。使用者問「能自動算嗎」,我的回覆是**可以算一半**:

- Excel `WORKDAY()` 排除週六日是內建的,但**國定假日要自己維護一份清單**
  (每年不同、還有補班日),清單沒更新算出來一樣是錯的。
- 更根本:營建契約的工作天通常還要扣**雨天等不可施工日**,那是現場認定的,
  日曆算不出來。系統算的永遠是下限。

建議:算出來當**參考值**顯示在畫面、標明「未扣除停工日」,**不回寫**主檔的
契約竣工日——不要產生一個看起來合法卻是錯的日期。要走這條需要他決定:
國定假日清單從哪來、參考值要不要進報表。**尚未實作,目前工作天仍照 B8+B7-1。**
