2026-08-06 使用者兩度退回我對專案 `.claude/CLAUDE.md` 的修改。第一次我只刪掉過期的
skipped 數字,他說「應該把有關跑測試的數量都拿掉」;我照做後他再問「是數字問題嗎?
跑測試這種東西有需要寫在 claude.md?」——真正的意見不是數字,是**整節都不該在那裡**。

判準:CLAUDE.md 只放「不看不會知道、猜錯要賠掉一輪」的事實。三類要刪:

1. **當場查得到的**——跑測試指令看 `package.json`、檔案結構看目錄。抄進規則檔只會過期。
2. **全域 CLAUDE.md 已有的**——輸出精簡、兩段式除錯、先量再優化。抄一份到專案檔會製造分岔,
   兩邊漂移後不知道該信哪個。
3. **任何會隨 commit 移動的數字**——通過數、skipped 數、秒數、輸出 bytes。下個 session 讀到
   過期值會再花一輪確認是不是有東西壞了,製造的正是它想防止的困惑。

**Why**:規則檔每個 session 都全文載入,長度直接換成每次的成本與雜訊;寫錯或寫舊的規則
比沒有規則更貴,因為它的權威性高於當下的觀察,會壓過我實際跑出來的結果。

**How to apply**:量完效能/測試想寫進 CLAUDE.md 前,先問「這件事 grep 一次能不能查到?
全域規則是不是已經講過?」兩題都否才寫,且寫成不隨 commit 漂移的敘述。實例:`SP0_SKIP_EXCEL=1`
這旗標只存在測試碼裡、`package.json` 查不到 → 留;「全跑 272 秒」→ 刪。
